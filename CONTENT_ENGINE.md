# Original Content Engine — YouTube, Instagram, GitHub and Portfolio

## Objective

Use original technical work as the source material for a repeatable media system that builds authority, creates inbound consulting leads and may later generate platform, affiliate or product income.

The principle is simple:

`real project → original evidence → long-form explanation → short-form derivatives → portfolio proof → lead magnet → consulting / product funnel`

AI assists with transformation and production. It does not invent projects, measurements, outcomes or experience.

## One-project production loop

For every suitable real project, collect:
- problem statement
- constraints
- architecture sketch
- anonymised screenshots / diagrams
- commands or configuration snippets that are safe to publish
- failures encountered
- decisions made
- measurable outcome where available
- what would be done differently next time

Then generate the following assets.

### A. Long-form YouTube

Target: one substantial video every 7–10 days during the launch phase.

Structure:
1. the operational problem
2. why obvious solutions were insufficient
3. constraints
4. architecture
5. implementation
6. what failed
7. troubleshooting
8. result
9. lessons / trade-offs
10. link to case study or consulting page

Avoid presenting tutorials as universal recipes when the advice depends on environment or risk.

## B. YouTube Shorts / Instagram Reels

Extract 3–6 short pieces from each long video.

Useful patterns:
- “The mistake”
- “The measurement that exposed the problem”
- “Why I chose X instead of Y”
- “One diagram in 45 seconds”
- “What broke after deployment”
- “Three checks before you…”

Short-form content should point back to the full explanation or case study.

## C. Instagram carousel

Suggested 7-card format:
1. problem / hook
2. existing system
3. constraint
4. architecture
5. key decision
6. result / lesson
7. case-study / consulting CTA

## D. GitHub case study

Keep the technical evidence durable:
- architecture
- configuration examples
- deployment notes
- decisions
- limitations
- reproducible public components

Do not publish secrets or sensitive institutional topology.

## E. Portfolio evidence hub

Each case study should answer:
- What was the problem?
- What was my role?
- What constraints mattered?
- What did I design / build / troubleshoot?
- What evidence exists?
- What was the outcome or current maturity?
- Which paid service does this prove?

## F. LinkedIn / written post

One concise decision-oriented article or post:
- problem
- surprising insight
- trade-off
- result
- diagram / screenshot

No generic motivational filler.

## G. Lead magnet

When a topic repeatedly attracts interest, produce a useful downloadable asset:
- Proxmox migration checklist
- TrueNAS permission audit checklist
- VLAN planning worksheet
- school technology audit checklist
- infrastructure handover checklist
- backup / restore verification sheet

The lead magnet should naturally connect to a paid audit or implementation service.

## AI production workflow

AI can assist with:
- transcript cleanup
- outline creation
- title variants
- thumbnail copy concepts
- extracting short-form segments
- converting a transcript into article drafts
- carousel draft text
- chapter markers
- captions
- metadata
- summarising code / configuration with human verification
- generating B-roll and diagram shot lists

AI must not fabricate:
- client outcomes
- benchmarks
- measurements
- failures
- testimonials
- certifications
- project scale
- screenshots or evidence represented as real

## Suggested recurring workflow

### Day 1 — Capture
Record the real project explanation while details are fresh.

### Day 2 — Long form
Edit the main YouTube video and prepare the case-study source.

### Day 3 — Derivatives
Use AI to identify 3–6 short clips, one carousel and one written post.

### Day 4 — Proof
Update GitHub / portfolio evidence and publish a relevant checklist if useful.

### Day 5 — Distribution and analytics
Review which topics produced qualified enquiries, not merely views.

## Commercial CTA hierarchy

Content should not constantly scream “hire me”. Use a natural ladder:

`watch → inspect proof → download checklist / explore portfolio → WhatsApp scoping → paid audit → implementation → retainer`
