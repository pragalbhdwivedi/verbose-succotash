# Consulting Playbook

## Positioning

**Pragalbh Dwivedi — Independent Infrastructure & Institutional Systems Consultant**

I design, troubleshoot and build self-hosted infrastructure, networks, storage and custom technology systems for organisations and educational institutions.

Primary market: international-first remote consulting, with India as a second market and travel available when the project justifies it.

## What to sell

Sell outcomes, not isolated tools.

- Do not sell “install Proxmox”. Sell a recoverable, documented virtualisation platform.
- Do not sell “configure TrueNAS”. Sell controlled storage, permissions, snapshots, backup and recovery.
- Do not sell “set up VLANs”. Sell a network architecture that separates users, servers, cameras, IoT and guests in a way the client can operate.
- Do not sell “school IT support”. Sell an institutional technology blueprint covering systems that must work together.

## Flagship offer: Infrastructure Rescue

Best for clients with infrastructure that is broken, fragile, undocumented or difficult to understand.

### Inputs
- host / VM / container inventory
- Proxmox configuration
- storage and ZFS information
- network / VLAN layout
- switch and firewall configuration where relevant
- Docker Compose / service inventory
- backup configuration
- logs, screenshots and current symptoms
- previous documentation, even if incomplete

### Deliverables
1. current-state architecture
2. critical-risk register
3. root-cause findings
4. immediate stabilisation actions
5. architecture recommendations
6. backup / recovery assessment
7. network / storage / virtualisation recommendations
8. implementation roadmap
9. updated system documentation

## Engagement process

### 1. Diagnose
Clarify the business problem, users, existing environment, risks, constraints and failure modes.

### 2. Architect
Produce the target architecture, decisions, trade-offs, implementation phases and recovery model.

### 3. Implement
Deploy or migrate the agreed system with checkpoints, validation and documentation.

### 4. Maintain
Offer monitoring, backup verification, updates, troubleshooting and documentation maintenance as a retainer.

## Client qualification

Prefer work where at least one is true:
- failure or downtime is expensive
- the client owns meaningful infrastructure
- multiple systems must integrate
- the environment is poorly documented
- the client needs architecture, not only labour
- the project can lead to implementation or recurring support

Avoid competing primarily for commodity installation work where the buying decision is almost entirely hourly price.

## Initial conversation

A brief scoping conversation can be free. Detailed diagnosis, architecture, implementation and documentation are paid work.

## Weekly operating model

At roughly 25–50 available hours per week:
- 40% client delivery
- 20% acquisition and proposals until pipeline is stable
- 15% recurring-service operations
- 15% internal automation / InfraLens
- 10% original content and case-study production

As client volume rises, acquisition time should fall and delivery should increasingly be standardised and delegated.
